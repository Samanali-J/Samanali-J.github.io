About

Where data engineering meets applied ML

“

Most of my work happens at the point where raw data turns into something someone can act on. I've built vector search systems with FAISS, trained and evaluated models with scikit-learn, and rebuilt messy exports into reports that non-technical teams can read without help, because a model is only worth building if the person on the other end can rely on what it tells them.

Responsible AI isn't something I add at the end. The mental health chatbot I built is grounded in retrieval, meaning it can only answer from documents it has actually pulled from four trusted organisations, because a hallucinated answer matters a great deal more when someone is asking about their own wellbeing. That habit of verifying output rather than trusting the first result carries through everything else I build.

Away from the technical side, I've spent the past two years running student events, mentoring classmates through machine learning coursework, and handling publicity for a cultural association with hundreds of members. Communicating findings to stakeholders who didn't build the model is a skill I use as often as the modelling itself.

Each project started with a real gap: data that existed but was not usable in its current form, or a hypothesis nobody had tested against evidence. The engineering work was in closing that gap reliably.

Eunoia — a grounded mental health chatbot

RAG System

Beyond Blue, Lifeline, Headspace and the Black Dog Institute all publish reliable information, but it's scattered across four sites. Eunoia indexes it into FAISS vector stores and searches a knowledge base and a Q&A bank in parallel, answering from whichever holds the closest match.

The problem

Language models hallucinate when unsure, which matters a lot more when someone's asking about their own mental health. I built a prompt-grounding guardrail that restricts every response to retrieved context, plus an evaluation framework to verify it actually worked.

Tracking alarm schedules across 82 donor centres

Data Pipeline

Australian Red Cross Lifeblood needed to verify whether the alarm schedule at each of its 82 donor centres matched real operating hours, previously checked by hand across hundreds of pages of PDFs. I built a four-script pipeline to extract, clean and reconcile both datasets, using the Claude Vision API to pull schedules out of documents pdfplumber and PyMuPDF couldn't parse alone.

The problem

Halfway through, the client's rules changed, some centres needed wider tolerance windows. I built a configurable rule layer into the reconciliation engine so it could keep flagging mismatches regardless of which rule applied.

The output feeds a Power BI dashboard with KPI cards and a site deep-dive, giving the team one place to catch scheduling errors before they become a real problem.

Do Reddit and YouTube talk about travel differently?

NLP & Network Analysis

Reddit leans to long threads, YouTube to short reactions, so comparing how the two platforms talk about travel needed a pipeline built for both. I collected posts and comments via PRAW and the YouTube Data API, extracted every country mention, and scored sentiment with VADER and transformer models.

The problem

A five-word comment and a three-paragraph thread can't be scored the same way. I standardised preprocessing across both sources, then tested whether sentiment differs by platform and whether countries mentioned together form real regional groups.

Building the co-mention graph in NetworkX and running Louvain community detection produced clusters that matched genuine regional groupings, which was the strongest sign the pattern was real.

Teaching a model to check an image against a caption

Deep Learning

Visual entailment asks whether a caption is actually supported by an image. I built and evaluated three architectures pairing ResNet50 with BERT, moving from simple concatenation through to cross-attention and self-attention.

The problem

Multiple captions can describe the same image, so a random split leaks correlated samples between train and test. I used stratified image-level splitting instead, then judged models on accuracy, AUC, precision and recall together.

A documented hyperparameter search lifted validation AUC from 0.71 to 0.82, and the final model reached 72% accuracy and 0.80 AUC on held-out data.
